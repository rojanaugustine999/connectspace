# Deploying ConnectSpace

```
Browser ──► Vercel (Next.js)  ──/api/* proxy──►  Render (Express API)  ──► Neon (PostgreSQL)
   │                                                 ▲    │                 └► Atlas (MongoDB)
   └──── Socket.io (2-minute token) ─────────────────┘    └──────────────► Cloudinary (images)
```

- The browser only talks to **Vercel**. Next.js forwards `/api/*` to Render, so the login cookie is
  first-party and works in every browser (including Safari and iPhones).
- Socket.io connects straight to **Render** with a 2-minute token from `GET /api/auth/socket-token`,
  because Vercel can't proxy WebSockets.

All services below have free plans. Do the steps in this order: each one needs a value from the one before.

---

## 1. MongoDB Atlas: allow Render to connect

Atlas → **Security → Network Access** → **Add IP Address** → **Allow access from anywhere** (`0.0.0.0/0`) → Confirm.
Render's servers don't have a fixed IP address. Your database password still protects the data.

## 2. Cloudinary: image storage

1. Sign up at https://cloudinary.com (free).
2. Dashboard → **API Keys** (or "Go to API Keys") → copy the **API environment variable**:
   `cloudinary://123456789:abcDEF...@your-cloud-name`
3. Keep it somewhere safe for step 4. It's a secret: never commit it.

## 3. GitHub: put the code online

1. https://github.com/new → name `connectspace` → **Private** → don't add a README/.gitignore → **Create**.
2. In the `connectspace` folder:
   ```bash
   git remote add origin https://github.com/<your-username>/connectspace.git
   git push -u origin main
   ```
   Your `.env` files are in `.gitignore`, so no passwords are uploaded.

## 4. Render: the API (Express + Socket.io)

1. https://render.com → sign up **with GitHub**.
2. **New → Blueprint** → choose the `connectspace` repo. Render reads `render.yaml`.
3. Fill in the secret values it asks for:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Your Neon string, the same as in `server/.env` |
   | `MONGO_URI` | Your Atlas string, the same as in `server/.env` |
   | `CLOUDINARY_URL` | From step 2 |
   | `CLIENT_URL` | For now: `https://example.com` (you'll fix it in step 6) |

   `JWT_SECRET` is generated by Render automatically. **Don't** add `DNS_SERVERS` (it's only for Windows).
4. **Apply**. The first build takes a few minutes. When it's live, open
   `https://connectspace-api.onrender.com/api/health` (your URL may differ). It should say `connected` twice.

## 5. Vercel: the website (Next.js)

1. https://vercel.com → sign up **with GitHub** → **Add New → Project** → import `connectspace`.
2. **Root Directory: `client`** (important!). Framework: Next.js (auto-detected).
3. **Environment Variables:**

   | Key | Value |
   |---|---|
   | `API_ORIGIN` | Your Render URL, e.g. `https://connectspace-api.onrender.com` |
   | `NEXT_PUBLIC_SOCKET_URL` | The same Render URL |

   No trailing slash on either.
4. **Deploy**. You get a URL like `https://connectspace-xyz.vercel.app`.

## 6. Connect them

Render → your service → **Environment** → set `CLIENT_URL` to your Vercel URL (no trailing slash) → **Save**.
Render redeploys automatically (Socket.io only accepts connections from this address).

## 7. Check that it works

- [ ] Open the Vercel URL → **Sign up** → you're logged in on `/me`
- [ ] Refresh: still logged in (the cookie works)
- [ ] Post with a photo: the image URL starts with `https://res.cloudinary.com/`
- [ ] Open a second browser (or a private window), log in as someone else, and chat: messages and "typing…" arrive live
- [ ] Safari / iPhone: log in works too

## Good to know

- **Same databases as development.** Right now local dev and the live site share the Neon and Atlas
  databases, so test data shows up live. When you want them separate: create a Neon **branch** and a
  second Atlas database for development, and point `server/.env` at those.
- **Render free plan sleeps** after 15 minutes without visitors. The first request after that takes
  about a minute. Open the `/api/health` URL first to wake it up before a demo.
- **Every `git push` to `main` redeploys both** Render and Vercel automatically. New Prisma migrations
  run on Render during the build (`prisma migrate deploy`).
- **Large uploads:** images go through the Vercel proxy. If uploads close to the 5 MB limit fail on the
  live site, lower `MAX_IMAGE_BYTES` (server) and `MAX_IMAGE_MB` (client) to 4.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Render deploy fails with "Can't start, please fix these environment variables" | A value from step 4 is missing; the log lists which |
| `/api/health` shows mongo `disconnected` | Atlas Network Access isn't `0.0.0.0/0` (step 1), or a typo in `MONGO_URI` |
| Website loads but every action fails | `API_ORIGIN` on Vercel is wrong. Redeploy Vercel after changing env vars |
| Chat/notifications never update live | `NEXT_PUBLIC_SOCKET_URL` (Vercel) or `CLIENT_URL` (Render) is wrong or has a trailing slash |
| Photos fail on the live site | `CLOUDINARY_URL` is missing or wrong on Render |
